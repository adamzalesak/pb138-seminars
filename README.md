# PB138 – REST API Assignment

A full-stack TypeScript monorepo. The backend is an **Express + tsoa** REST API; the frontend is a **React + Vite** app that consumes it via generated React Query hooks.

## Prerequisites

- **Bun** — install from https://bun.sh

## Getting started

```bash
# 1. Install dependencies
bun install

# 2. Generate routes, OpenAPI spec, and frontend client code
bun run generate

# 3. Start both apps in watch mode
bun run dev
```

| URL | What |
|---|---|
| http://localhost:3000 | REST API |
| http://localhost:3000/api-docs | Swagger UI — explore and test all endpoints |
| http://localhost:5173 | React frontend |

> **Note:** `bun run dev` already runs `bun run generate` first, so step 2 is only needed separately if you want to inspect generated files before starting the dev server.

## Scripts

Run from the repo root:

| Command | Description |
|---|---|
| `bun install` | Install all workspace dependencies |
| `bun run generate` | Generate tsoa routes + OpenAPI spec (server), then TypeScript types and React Query hooks (web) |
| `bun run dev` | Start both apps in watch mode |
| `bun run build` | Build all packages for production |

To target a single package: `bun run --filter server generate`, `bun run --filter web dev`, etc.

## Why Turborepo?

This project uses [Turborepo](https://turbo.build/) as a monorepo task runner on top of Bun workspaces:

- **Parallel execution** — `bun run dev` starts both dev servers simultaneously
- **Task dependencies** — ensures correct execution order (e.g., `generate` before `dev`)
- **Build caching** — skips tasks whose inputs haven't changed, speeding up repeated builds

## Project structure

```
apps/
  server/   Express + tsoa REST API
  web/      React + Vite frontend
```

### Backend layers

| Layer | File pattern | Responsibility |
|---|---|---|
| **Model** | `*.model.ts` | TypeScript interfaces — shape of data only, no logic |
| **Repository** | `*.repository.ts` | Raw data access (in-memory array, or a DB in production) |
| **Service** | `*.service.ts` | Business logic and input validation (Zod schemas live here) |
| **Controller** | `*.controller.ts` | HTTP concerns: routing, status codes, request/response mapping |
| **Routes** | `src/generated/routes.ts` | Auto-generated by tsoa — do not edit |

Request flow: `HTTP → Routes → Controller → Service → Repository`

### Code generation

- `bun run --filter server generate` runs tsoa, which reads the controller decorators and produces:
  - `apps/server/openapi.json` — the OpenAPI 3 spec
  - `apps/server/src/generated/routes.ts` — Express route bindings
- `bun run --filter web generate` runs kubb, which reads `openapi.json` and produces:
  - `apps/web/src/generated/` — TypeScript types, axios clients, React Query hooks

Both outputs are git-ignored and must be regenerated after pulling or changing controllers.

## Student tasks

The `students` module is fully implemented and serves as a **reference implementation**. Read it before starting.

### Task 1 — Course filtering

**File:** `apps/server/src/modules/courses/courses.service.ts`

The `getAll` method currently ignores all filter parameters and returns every course. Implement the four cases marked with `// TODO`:

- `semester` — keep only courses matching the given semester
- `tags` — keep only courses that have **all** of the requested tags
- `minCredits` / `maxCredits` — keep only courses within the credit range

### Task 2 — Instructor creation

**Files:** `apps/server/src/modules/instructors/instructors.service.ts`

The `POST /instructors` endpoint is wired up in the controller but the service method throws `Not implemented`. Your job:

1. Define a Zod schema for `CreateInstructorBody` (validate `firstName`, `lastName`, `email`, `department`).
2. In the `create` method: parse the body with the schema, then pass the validated data to `instructorsRepository.create()`.

Reference: `apps/server/src/modules/students/students.service.ts`
